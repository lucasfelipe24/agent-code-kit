# Decisions: docs-site

Answered by the maintainer on 2026-09-30 unless marked *(planner)*.

## Decision 1: Site lives in `web/`, generated content built in CI

**Chosen**: A `web/` project in this repo with its own `package.json`. Pages
for skills, agents and guides are generated by `scripts/gen-skill-docs.sh`
during the build and are gitignored. Only hand-written pages are committed.
**Alternatives**: `web/` with the generated pages committed, plus a CI drift
check (every skill edit then produces a second diff). A separate site repo
(two repos to keep in step).
**Rationale**: The kit's sources stay the single source of truth, the diffs
stay small, and the generator already targets a `web/content/docs` tree.

## Decision 2: GitHub Pages at the github.io URL

**Chosen**: `https://lucasfelipe24.github.io/agent-code-kit/`, with the Next
`basePath` `/agent-code-kit` and a static export.
**Alternatives**: A custom domain with a CNAME.
**Rationale**: It needs no DNS. A domain can come later by dropping the
basePath and adding a CNAME.

## Decision 3: English + pt-BR

**Chosen**: Fumadocs i18n with `en` as the default and `pt-BR`. The landing
and the hand-written pages exist in both languages. Generated pages fall back
to English.
**Alternatives**: English only.
**Rationale**: The kit already keeps `README.pt-BR.md`. Translating generated
pages would fork the kit's sources, so they stay English (Not Now).

## Decision 4: Dependencies isolated in `web/package.json`

**Chosen**: next, react, fumadocs-core/ui/mdx and tailwindcss, only in
`web/package.json`. The kit's `package.json` gains no dependency. Recorded as
ADR-036.
**Alternatives**: Discussed in ADR-036.
**Rationale**: The kit ships with zero runtime dependencies. The site is a
maintainer artifact that the npm `files` list and `.kit-manifest` never
include.

## Decision 5: Generated pages are `.md`, not `.mdx` *(planner)*

**Chosen**: The generator writes plain markdown with frontmatter.
**Alternatives**: Keep `.mdx` and escape `<`, `{`, `}` and HTML comments in
every source.
**Rationale**: Kit docs are markdown written for GitHub. Escaping them for MDX
is a lossy transform that breaks on every new construct. Hand-written pages
stay `.mdx` so they can use Fumadocs components.

## Decision 6: Source paths in one table, R2 path first *(planner)*

**Chosen**: A path table at the top of the generator. For each source it tries
the layout-2 path (`.claude/kit/docs`, `.claude/agents/kit`) and then the
current path.
**Alternatives**: Wait for R2 to finish, or hard-code today's paths and fix
them in R2.
**Rationale**: R2 moves categories PR by PR (ADR-035), so the site keeps
building in every intermediate state.

## Decision 7: Own visual identity *(planner)*

**Chosen**: A palette from the kit's logo (navy → blue → cyan, violet
accent), dark-first. The landing is built around what the kit uniquely does:
a transcript of a hook blocking an action and the loop as a diagram.
**Alternatives**: Follow the reference site's layout (Roman-numeral sections,
before/after columns, live stats).
**Rationale**: The maintainer asked not to copy the reference. The logo
already defines a brand.

## Decision 8: Guide pages come from the README sections *(planner, during implementation)*

**Chosen**: The generator cuts `README.md` and `README.pt-BR.md` into guide
pages, keyed by the emoji both READMEs share on every `##` heading. It
rewrites the README's anchors to the page and section they land on and turns
`<details>` into headings. Only `index.mdx` / `index.pt-BR.mdx` and the root
`meta.json` are hand-written.
**Alternatives**: Hand-written intro, quick start, workflows and FAQ pages in
both languages (the approved plan, step 4).
**Rationale**: Hand-written pages would be a second copy of the README that
drifts. The READMEs already exist in both languages, section for section, so
pt-BR gets real content for free. The cost is that the generator fails loudly
if a README loses one of the expected sections.

## Decision 9: Skill groups follow the README *(planner, during implementation)*

**Chosen**: The sidebar groups and the landing's skill index use the README's
groups (Plan, Build and debug, Review and audit, Ship, Memory and reports,
Project setup) and its one-line descriptions, in both languages. A skill that
no group lists goes to "Other" and is reported by the generator.
**Alternatives**: A fixed Audit / Workflow / Meta table in the generator (plan,
step 3).
**Rationale**: One grouping for the README and the site. A second table would
be a second source.

## Decision 10: Install tabs are npx and curl only *(planner, during implementation)*

**Chosen**: The landing offers `npx` and `curl`.
**Alternatives**: A third "plugin" tab, as on the reference site.
**Rationale**: The README does not document a plugin install path, and
`web/DESIGN.md` forbids product claims the kit's sources don't make.
